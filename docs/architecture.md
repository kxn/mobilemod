# 架构与扩展

```text
运营商短信 → LuatOS 原始分片回调
                ↓ 模块 Flash JSONL 暂存
            USB JSON 行协议 v3
                ↓ 电脑 bbolt 事务落盘后 ACK
      原始分片 → 分组/到期处理 → 消息 + outbox（同一事务）
                                      ↓ 重试、稳定 UUID
                                  飞书消息 API

飞书用户命令 → 官方 SDK WebSocket → 用户/群 ACL、时效、消息 ID 去重
                                      ↓ 持久化命令任务
                 解析/短短信校验/限额 → 发送意图落盘
                                      ↓ 每模块串行发送
                                 USB → SMS API
```

| package | 职责 |
| --- | --- |
| `cmd/mobilemod` | CLI、信号与配置入口 |
| `config` / `domain` | 严格配置校验、协议和领域数据 |
| `phone` / `admin` | 号码规范化、Web 管理、口令与会话、请求来源保护 |
| `store` | bbolt 事务、单实例锁、落盘 |
| `modem` | JSON 帧、并发请求分发、重连、物理身份绑定、每模块发送串行化 |
| `sms` | Unicode/GSM 编码长度校验、持久化分片组装、缺片与冲突 |
| `notify` | 文本格式、长通知分块、持久化发送队列与退避 |
| `feishu` | 官方 WebSocket SDK、事件归一化、token 缓存和发送消息 API |
| `bot` / `forwarding` | 命令语法、受配置限制的运营商短信模板 |
| `service` | ACL、持久化任务、发送记录/限额、恢复、生命周期与健康接口 |
| `firmwaretest` | 用 GopherLua 执行真实 Lua 源码的硬件模拟测试 |

数据库 buckets：`raw` 原始事件、`groups` 长短信组、`messages` 转发消息、`outbox` 飞书发送队列、`commands` 用户任务、`sends` 短信发送记录、`settings` 物理绑定和告警去重、`number_bindings` 按 SIM 哈希绑定的手工号码、`replies` 飞书消息 ID 到原短信的关联。没有关闭 bbolt 的同步写入。进程中断后运行中的命令不会重新执行，回复明确提示检查结果；待执行但超过五分钟的命令失效。

长短信分组键含逻辑模块、SIM ICCID 的哈希、来源号码、参考号和总片数。原始事件 ID 使用模块、模块启动号、持久化序号去重。同片同内容重复忽略；同片不同内容保留原片和冲突通知；乱序片按序号拼接。关闭组暂存以抑制重放和识别参考号复用。

接收号码使用事件自带号码；事件号码缺失但 SIM 与当前状态一致时使用最近读到的号码。手工号码绑定 SIM 身份并可随卡移到另一模块；旧 SIM 重放事件使用旧 SIM 的绑定，不借用新卡号码。Web 保存携带读到的 SIM 哈希，已经换卡的页面请求被拒绝。

默认由 USB 发现器管理连接生命周期，每三秒枚举应用接口，握手读取设备 ID，再向运行时注册或复用模块。端口只属于当前连接，设备身份和 SIM 号码分别管理。注册表支持并发读取，插拔不重启主进程；手工串口模式仍可显式关闭自动发现后使用。

发送先按规范化号码匹配唯一在线模块，保留其 SIM 身份和号码快照；取得发送锁后再次校验，并查询新鲜状态。USB 请求携带 expected_iccid，Lua 在调用 SMS API 前比对当前卡。主机查找期间、发送排队期间和命令到达模块后的换卡均有保护；用户手工填写的号码仍需自行保证准确。

飞书通知返回的 message_id/chat_id 与原短信路由快照同事务落盘，每个长通知分块都保存关联。引用回复直接读取本地关联，找不到时提示使用 /sms。未投递通知携带自身路由快照，原短信到期清理后仍可在投递时建立关联。

Web 静态资源通过 Go embed 提供，不引入额外前端运行时。默认绑定 loopback，也支持局域网访问。首次设置使用服务端初始化码；管理口令使用带盐 PBKDF2，修改即撤销旧会话。API 依靠登录 Cookie、同源写入和 JSON 请求，不另维护 Host 白名单或 CSRF token。页面用 textContent 显示数据，不回显飞书密钥。动态飞书凭据验证成功后保存并重建长连接；启动失败重试，不影响 Web 修复或短信落盘。HTTP 局域网访问须在可信网络，需要加密时使用 SSH 隧道。

目前 UART/USB 是本机受信任边界，固件不提供远程认证。不要把串口直接转发到公网。电脑服务不提供任意 AT、Lua、shell 或任意 URL 下载命令。飞书 SDK 日志被限制，避免输出带凭据的连接 URL；程序正常日志不记录短信正文或密钥。数据库和飞书会保存明文消息，应限制系统账户、应用可用范围和群成员。

## 呼叫转移适配

Air780EPM/106 没有本项目可调用的拨号、MMI 或 CCFC 控制接口；当前 `unsupported` 是实际能力限制。运营商业务代码不等于普通电话号码，不能直接交给短信发送，也不能仅凭本地缓存当成查询结果。

若运营商明确提供该号码套餐支持的业务短信，可设置：

```json
{
  "backend": "sms",
  "service_number": "运营商确认的业务号码",
  "query": "运营商确认的查询正文",
  "set": {"unconditional": "运营商模板含{number}占位符"},
  "cancel": {"all": "运营商确认的取消正文"}
}
```

以上是结构说明，不能原样使用；项目没有内置猜测的业务号码或指令。未配置的类型明确拒绝；所有业务短信经过相同的短短信长度、目的号码白名单、发送限额和持久化记录。发送成功只表示业务短信提交成功，运营商确认消息会作为普通短信转发。需要真实网络状态查询的后续硬件，应实现独立 backend 并保留真实响应，不能用最近一次设置值代替。

## 彩信

当前 [官方 SMS API](https://docs.openluat.com/osapi/core/sms/) 明确不支持彩信；已验证固件仅暴露解码后的短信回调。不能根据一个 URL 就实现彩信，因为还需要 WAP Push 解码、对应 SIM 的 MMS APN/PDP、MMSC 协议与附件解析。项目接受未来驱动的 `mms_received` 事件作降级通知，地址仅显示，不访问；它不是当前模块已支持彩信的声明。

更换支持原始 PDU/WAP Push 与专用 MMS PDP 的模块后，可新增传输适配器和受限下载器，独立限制大小、类型、超时和访问地址，再使用飞书文件 API。当前版本没有该下载器。
