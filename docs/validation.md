# 验证范围

完整、可追踪的最新结果见仓库的 GitHub Actions。自动测试使用本地模拟器和虚构标识，不需要真实 SIM、飞书应用或测试凭据，也不会发送收费短信。

## 自动验证

- CI 在一个 Linux amd64 runner 上执行一次带 race 和覆盖率的全部测试，以及 go vet。
- 一套 Gitleaks 同时检查密钥与个人标识，另做依赖漏洞检查。
- 发版时交叉编译五种 64 位系统/架构组合，生成包和 SHA256 校验和，不重复跑 CI。
- 模糊测试保留为手动开发工具，不在每次 push 自动执行；CI 不访问真实飞书或短信网络。

## 硬件验证摘要

在 Air780EPM / V2044_106 / 协议 2 桥接程序上，曾验证：SIM 号码读取、网络注册、短短信提交，以及 190 字中文长短信自身回环，三片组装后真实转发飞书且正文逐字一致。公开仓库不包含这些测试账号、个人号码、会话标识、数据库或原始联调日志。

这项硬件测试使用联通卡；电信卡仍需针对实际 SIM 进行双向验证。只有 Windows 连接过实机；其他平台的 CI 和交叉编译不能代替实际 USB 驱动及运营商联调。

协议 3 桥接已在实机刷入，发送前 SIM 校验能力可查询。Web 管理页已在真实浏览器验证保存/清空号码、自动号码优先和手机尺寸无横向溢出。实际从联通换电信后，检测到了 SIM 变化；旧号码未沿用，新号码随后自动读取，网络注册和短信就绪正常。本轮没有主动发送电信短信，故不把注册就绪当作电信双向短信验证。

两张卡分别做过来电拨测，模块在线但均未观察到 INCOMINGCALL。实现中保留被动事件处理，不能据此宣称该 EPM/106 具备可靠来电通知能力；详细调查见 incoming-calls.md。

当前模块没有可用的呼转控制 API，也没有彩信载荷下载入口。测试模板或通知降级接口不代表硬件已支持对应功能。有限模块存储、Flash 掉电窗口、短信参考号复用和飞书至少一次投递等边界见 README。
