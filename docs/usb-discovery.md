# USB 自动发现与热插拔

默认启用 `auto_discover`，`modules` 可以为空。启动时没有模块，服务照常运行；每三秒扫描一次 USB 应用串口，插入后自动连接。拔出后标记离线，其他模块和飞书连接继续运行；重新插入时重新枚举，所以 COM 号或 tty 名称变化不需要修改配置。

识别分为两步：先匹配当前 Air780EPM 固件的 USB 标识 VID 19D1、PID 0001、应用接口 06，排除诊断/日志口；再发送桥接协议的 status 查询，读取物理设备 ID。不会用某个固定 COM 号或 tty 序号猜模块，也不会发送短信或 AT 指令来探测。

Windows 读取当前串口列表和 USB 接口注册信息；Linux 读取 sysfs 的 USB 标识与接口编号；macOS 通过 ioreg 读取相同的 USB 信息，不需要 CGO。设备须已经刷入本项目桥接程序，且系统有相应 USB 串口驱动和访问权限。Windows 已在当前设备验证枚举和自动接入；Linux 接口选择有模拟 sysfs 测试，其他平台仍需实机确认。

自动新增模块的 ID 为 `usb-` 加设备 ID 的摘要，跟随物理模块，独立于端口和 SIM。既有数据库里的模块名称与绑定会继续使用。号码仍按 SIM 自动读取/手动配置，换卡和换 USB 口是两件独立的事。

如需给某只设备指定名称，可配置 `modules` 条目，填写 `id` 和 `expected_device_id`，不需要 port。发送命令仍按手机号选模块。

如果需要完全手工指定端口，显式设置 `auto_discover: false`，并为每个模块填写 port；这是可选模式。Linux 手工模式建议使用 `/dev/serial/by-id/` 路径。

没有在线且短信就绪的模块时 `/readyz` 返回 503，`/healthz` 仍返回 200。这表示没有可用的短信设备，不代表进程退出。
