# 来电通知：库支持与被动事件的区别

当前目标为 Air780EPM、V2044/106。官方 [cc 支持说明](https://docs.openluat.com/osapi/core/cc/) 和 [EPM 固件矩阵](https://docs.openluat.com/air780epm/luatos/firmware/780epm_version/) 均未提供 EPM 的 cc 库，因此不能通过公开 Lua API 初始化通话、读 cc.lastNum、接听或拨号。短信可用不等于 VoLTE 语音可达。

进一步检查 [官方 mobile 绑定源码](https://github.com/openLuat/LuatOS/blob/master/components/mobile/luat_lib_mobile.c) 可见，通用移动层会把底层通话指示发布为 CC_IND，包括 INCOMINGCALL。这说明“没有 cc 函数库”不能单独证明“绝不可能观察到被动来电事件”；但通用源码存在这条分支，也不保证 EPM/106 基带会向它提交事件。

本程序因此只注册被动监听，不调用 cc.init、accept、dial、hangUp，也不改 VoLTE 设置。如果底层实际上报，通知进入与短信相同的持久化队列，再送飞书；重复振铃在同一通话内去重。来电号码仅使用事件中实际给出的号码或可用的 cc.lastNum；两者都没有时明确显示未知。通用 mobile 事件本身通常不携带号码，不能承诺在缺少 cc.lastNum 的 EPM 上得知主叫。

管理页“监听中，未观察到来电事件”表示监听已部署但本次开机尚无 INCOMINGCALL；“已观察到来电事件”仅表示本次开机曾收到真实 INCOMINGCALL，不等于完整语音功能受支持。通知中的时间优先使用模块提供的有效事件时间；没有有效设备时间时使用电脑收到通知的时间并注明。

联通卡拨测中主叫提示无法接通，电信卡拨测中主叫提示关机；两次测试时模块都在线、已驻网、短信就绪，但未观察到 INCOMINGCALL。电信卡也已成功自动读取本机号码。这些结果不支持将当前 EPM/106 用作可靠的原生来电通知设备。运营商可能另外发送短信提醒，这类消息继续按普通短信完整转发；它与模块直接观察来电不是同一种证据。换运营商、固件或卡后仍须实测，不能仅凭注册信号/短信就绪或一次拨号提示确定原因。

若终端没有注册为可接收 VoLTE 语音的设备，网络可能给主叫返回不可达；但相同提示也可能来自卡业务配置或网络状态。没有相关信令和运营商确认时，只能保留为可能原因，不能断言基站直接检测到“没有语音硬件”。当前版本不承诺 EPM 的可靠来电通知。
