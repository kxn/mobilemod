# Web 管理、认证与号码选择

默认地址为 `http://127.0.0.1:8765/`（也支持 localhost）。端口由已有的 `health_listen` 控制；设为空会同时关闭管理页和健康接口。页面资源编入 Go 二进制，不需要安装 Node、构建前端或访问外部 CDN。

## 首次设置与登录

首次启动会在数据库同目录生成 `admin-setup-code`，Linux 权限为 0600。服务日志仅提示文件位置，不打印初始化码。通过 SSH 或服务器终端读取文件，在 Web 输入此码并设置至少 12 字节的管理口令。初始化码仅能使用一次，设置成功后删除；未初始化时，状态、号码和飞书设置 API 均不可访问。

```sh
sudo -u mobilemod cat /var/lib/mobilemod/admin-setup-code
```

之后使用管理口令登录。口令以随机盐和 PBKDF2-SHA256（600000 次）保存，页面和 API 不回显。登录会话有效期 12 小时，Cookie 使用 HttpOnly、SameSite=Strict；退出立即失效。在“网关设置 → 管理口令”输入旧口令和新口令即可修改，所有其他会话立即失效。认证接口限制每分钟最多 10 次尝试，重启会清空会话。

## 局域网部署

在 Linux 配置文件设置 `"health_listen": "0.0.0.0:8765"`，然后访问 `http://服务器局域网IP:8765/`；IPv6 可配置 `[::]:8765`。也可使用指向服务器的局域网域名。默认仍绑定本机，不会自动改变当前机器网络或防火墙。

所有管理 API 都要求登录；`/healthz` 和 `/readyz` 仅返回健康状态，不要求登录。HTTP 本身不加密，因此仅在可信局域网直接使用；需要加密访问时保持 loopback 绑定并通过 SSH 端口转发访问。不要直接暴露到公网。首次远程设置仍需服务端初始化码，不能由任意访客抢设口令。

## 飞书认证

登录后在“网关设置 → 飞书认证”修改 App ID 和 App Secret。密钥永不回显；同一 App ID 留空密钥可保留原值，更换 App ID 必须提供新密钥。服务只调用 token 接口验证，不发测试消息；验证或数据库保存失败时保留原配置，成功后保存并重新建立长连接，不需要重启模块或服务。

Web 保存的凭据优先于配置文件和环境变量，保存在当前数据库，重启后继续生效；配置文件不会被改写。密钥在数据库中以明文保存，数据库和备份须仅允许服务账户访问。若要完全从 Web 首次填写，可把配置中的 app_id 和 app_secret 同时留空，并关闭 secret_env（或确保其为空），同时启用 Web 管理；连接建立前仍可接收短信到本地队列。allowed_users、allowed_chats、recipients 仍由私有配置文件管理，更换飞书应用时须核对这些应用相关标识和权限。

模块卡片显示串口、固件、当前接收号码、号码来源、网络/信号、短信就绪及被动来电状态。页面每五秒刷新，也可手动刷新。实际手机号只从本机 API 获取，不写进静态网页或发布包。

## 号码优先级

1. 当前 SIM 的 API 返回有效本机号码时，优先采用并显示“由 SIM 自动读取”。
2. SIM 没有提供号码时，使用在本页为该 SIM 保存的手工备用号码。
3. 两者都没有时，转发消息标注模块 ID；按号码发送需先补齐号码。

国内手机号可省略 +86；保存后统一为带国别码形式。留空保存可清除备用号码；自动号码存在时，清除备用不会影响当前自动号码。用户填写的号码仍须自行确认与 SIM 实际号码相符。

手工记录按 SIM 身份保存，不按 COM 端口保存；换卡后不继承旧卡号码，旧卡移动到另一已配置模块时可带着它的手工记录。SIM 身份未知或模块离线时不能编辑。保存请求包含页面所见的 SIM 标识，发生换卡时旧页面请求被拒绝，避免把号码误填给新卡。

旧配置文件的 `number` 只在对应模块第一次识别 SIM 时导入一次，不会在每次重启/换卡后反复覆盖 Web 设置。升级后应在页面核对已有手工号码。配置文件不被 Web 改写，动态设置和回复关联都保存在本地数据库，备份时需包含数据库。

## 发信与回复

`/sms <发送号码> <目标号码> <正文>` 按规范化的发送号码查找唯一在线模块。重复号码、未知号码和卡片离线均会报错。发送锁取得后、读取新鲜 SIM 状态后和 Lua 真正提交前均检查卡身份。

正文从目标号码后第一个分隔空白之后开始，后续字符原样保留，包括用于表示正文前导空格的额外空格、连续空格、换行和末尾空格。空正文或仅空白会拒绝；合法正文不会被剪裁。短信长度仍按真实正文计算，不会通过修剪空格使超长短信变短。

引用回复通过本地保存的消息关联找到原短信。0.4 之前没有保存关联的转发消息，请改用 /sms。原号码不在线时报错；原号码当时未知时，只能用仍在线的同一 SIM 在补齐号码后回复。不会把旧物理模块里的新 SIM 当成原卡。

## 访问边界

管理 API 要求登录，写入要求同源 Origin 和 JSON；会话 Cookie 使用 SameSite=Strict，不另维护 CSRF token 或 Host 白名单。不开放 CORS，也不信任 X-Forwarded-* 请求头。页面数据不缓存，显示文本使用 textContent。号码、飞书密钥、初始化码和管理口令均不写入静态网页或公开发布包。
