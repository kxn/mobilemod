# 本机管理页与号码选择

默认地址为 `http://127.0.0.1:8765/`（也支持 localhost）。端口由已有的 `health_listen` 控制；设为空会同时关闭管理页和健康接口。页面资源编入 Go 二进制，不需要安装 Node、构建前端或访问外部 CDN。

模块卡片显示串口、固件、当前接收号码、号码来源、网络/信号、短信就绪及被动来电状态。页面每五秒刷新，也可手动刷新。实际手机号只从本机 API 获取，不写进静态网页或发布包。

## 号码优先级

1. 当前 SIM 的 API 返回有效本机号码时，优先采用并显示“由 SIM 自动读取”。
2. SIM 没有提供号码时，使用在本页为该 SIM 保存的手工备用号码。
3. 两者都没有时，转发消息标注模块 ID；按号码发送需先补齐号码。

国内手机号可省略 +86；保存后统一为带国别码形式。留空保存可清除备用号码；自动号码存在时，清除备用不会影响当前自动号码。用户填写的号码仍须自行确认与 SIM 实际号码相符。

手工记录按 SIM 身份保存，不按 COM 端口保存；换卡后不继承旧卡号码，旧卡移动到另一已配置模块时可带着它的手工记录。SIM 身份未知或模块离线时不能编辑。保存请求包含页面所见的 SIM 标识，发生换卡时旧页面请求被拒绝，避免把号码误填给新卡。

旧配置文件的 `number` 只在对应模块第一次识别 SIM 时导入一次，不会在每次重启/换卡后反复覆盖 Web 设置。升级后应在页面核对已有手工号码。配置文件不被 Web 改写，动态设置和回复关联都保存在本地数据库，备份时需包含数据库。

## 发信与回复

`/sms <发送号码> <目标号码> <正文>` 按规范化的发送号码查找唯一在线模块。重复号码、未知号码和卡片离线均会报错。发送锁取得后、读取新鲜 SIM 状态后和 Lua 真正提交前均检查卡身份。

正文从目标号码后第一个分隔空白之后开始，后续字符原样保留，包括用于表示正文前导空格的额外空格、连续空格、换行和末尾空格。空正文或仅空白会拒绝；合法正文不会被剪裁。短信长度仍按真实正文计算，不会通过修剪空格使超长短信变短。

引用回复只对已验证的转发短信有效，不能通过伪造一段转发文本指定收信人。旧版本消息只有在飞书确认当前应用发送、会话一致，并与仍保留的本地原短信逐字匹配时才恢复关联。原号码不在线时报错；原号码当时未知时，只能用仍在线的同一 SIM 在补齐号码后回复。不会把旧物理模块里的新 SIM 当成原卡。

## 访问边界

管理服务只允许绑定 loopback，API 检查 Host、同源 Origin、JSON 类型及随机 CSRF token；未开放 CORS。页面设置 CSP 和禁止嵌入策略，数据不缓存，显示文本不用 innerHTML。此页属于本机用户信任边界，不应通过不受保护的反向代理或端口转发暴露到网络。
